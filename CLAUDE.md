# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this project is

A fully-automated deploy/teardown pipeline for a DealersEdge AI marketing chatbot hosted on AWS. The infrastructure is defined in `rag_template.yaml` (CloudFormation), with two wrapper scripts (`deploy.py` / `teardown.py`) that handle prerequisites and cleanup that CloudFormation alone can't manage.

## Deploying and tearing down

```bash
# Full deploy (default: --profile bedrock-course, --region us-east-1, --stack-name parts-assistant)
python3 deploy.py

# Upload knowledge base files after deploy
python3 deploy.py --kb-files /path/to/posts/

# Tear down everything (prompts for confirmation)
python3 teardown.py
```

Deploy runs 7 ordered steps:
1. ACM certificates (us-east-1, Route53 DNS validation)
2. WAF Web ACLs (CLOUDFRONT scope, must be us-east-1)
3. Build Lambda zips and upload to S3
4. Pre-flight check for orphaned retained resources
5. `aws cloudformation deploy`
6. (Optional) upload KB files to S3 and trigger Bedrock sync
7. Route53 CNAME records pointing to CloudFront distributions

## CloudFormation parameters

`parameters.json` stores all parameter values including ARNs for pre-created resources (ACM certificates, WAF ACLs). `deploy.py` writes ARNs back to this file when it creates new resources. Keep this file committed so the stack can be redeployed without re-creating those resources.

`SENTINEL = "{GENERATED BY deploy.py AT RUNTIME}"` in any ARN field means deploy.py will create or discover that resource.

## Lambda functions

Three Lambdas, each in its own subdirectory:

| Directory | Stack resource | Runtime | Role |
|---|---|---|---|
| `rag-ingest/` | `{AppName}-rag-ingest` | Python 3.13 | Pulls product catalog from Google Sheets, downloads PDFs/MP4s to S3, triggers Bedrock KB sync |
| `rag-node/` | `{AppName}-rag-node` | Node.js 24.x | Retrieves KB chunks then streams answer via ConverseStream; uses `us.anthropic.claude-sonnet-4-6` |
| `rag-log-indexer/` | `{AppName}-rag-log-indexer` | Python 3.13 | Scans `logs/` in S3, writes `manifest.json` files by year |

`rag-node/` also contains an unused `lambda_function.py` — the deployed function is `index.mjs`.

### Quick Lambda update (without full redeploy)

```bash
# Node function
cd rag-node && zip -r ../rag-node.zip index.mjs node_modules/
aws lambda update-function-code --function-name parts-assistant-rag-node --zip-file fileb://../rag-node.zip --profile bedrock-course

# Python function (no build step)
zip rag-ingest.zip rag-ingest/lambda_function.py
aws lambda update-function-code --function-name parts-assistant-rag-ingest --zip-file fileb://rag-ingest.zip --profile bedrock-course
```

`rag-ingest/` has a `package/` subdirectory bundling `google-auth`, `gspread`, and dependencies — `_build_ingest` in `deploy.py` zips `package/*` first, then `lambda_function.py` at the top level.

## S3 bucket layout

The single data bucket (`{AppName}-rag-chatbot-data`) has three path prefixes:
- `/front/` — chatbot HTML/JS/CSS served by the chatbot CloudFront distribution
- `/logs/YYYY/MM/DD/` — per-request audit logs (JSON), plus `logs/manifest.json` and `logs/YYYY/manifest.json`
- `/knowledgebase-files/` — source documents ingested by Bedrock (PDFs, MP4s, plus `.metadata.json` sidecar files)
- `system_prompt.txt` — loaded at cold-start by `rag-node/index.mjs`

## Retained resources

Several resources have `DeletionPolicy: Retain` so stack deletion doesn't destroy data:
`DataBucket`, `ChatbotDistribution`, `LogsDistribution`, `LogsPasswordProtectFunction`, `IngestFunction`, `RagNodeFunction`, `LogIndexerFunction`, `KnowledgeBase`, `KnowledgeBaseDataSource`, all three EventBridge schedules, and `RagNodeFunctionUrl`.

`teardown.py` deletes these retained resources after the stack is gone. `deploy.py` step 4 (pre-flight check) will abort if any of them already exist under the expected names before deployment — delete them manually using the commands it prints.

## EventBridge schedules

- `{AppName}-hourly` — triggers `rag-ingest` every hour (enabled)
- `{AppName}-every-15-minutes` — triggers `rag-ingest` at :15/:30/:45 (disabled by default)
- `{AppName}-nightly` — triggers `rag-log-indexer` daily at 11:44 UTC (enabled)

## Guardrail

`rag-node/lambda_function.py` has a Bedrock Guardrail (`8kow3zjhftvg` v1) wired up but both call sites (input and output) are commented out. The active Node.js implementation (`index.mjs`) has no guardrail.

## Dependencies

Python: `boto3` (system), `google-auth`, `gspread` (bundled in `rag-ingest/package/`).  
Node.js: `@aws-sdk/client-bedrock-agent-runtime`, `@aws-sdk/client-bedrock-runtime`, `@aws-sdk/client-s3` (in `rag-node/node_modules/`).
